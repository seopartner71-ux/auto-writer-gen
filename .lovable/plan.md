# AI Traffic Monitor - план

Раздел для администратора: мониторинг ИИ-ботов и переходов из ИИ-чатов по сайтам клиентов. Каждый сайт считается отдельно. Демо-цифр нет: если источник не подключен, показываем «Не подключен» и пустое состояние.

## Что уже есть и что используем
- Роль администратора уже хранится в отдельной таблице ролей, а серверная проверка `requireAdmin` уже есть. Новую систему ролей не делаем.
- Журнал ботов (метка в архивах) и страница «Аналитика ботов» остаются как есть. Существующие записи можно показать как источник «Метка в архиве», отдельно от логов сервера.

## Этап 1. Реестр сайтов
- Список сайтов клиентов: название, домен, статус подключения, источники данных, дата последней проверенной синхронизации.
- Для каждого сайта создается свой секретный ключ сборщика. Полный ключ показывается один раз, в базе хранится только его хеш.

## Этап 2. Справочники
- Боты: название, признак в User-Agent, категория (ИИ-сборщик, ИИ-поиск, запрос пользователя ИИ, поисковый робот). Начальный список: GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-SearchBot, PerplexityBot, Googlebot, Bingbot, Яндекс. Googlebot и Bingbot относятся к поисковым роботам.
- Источники переходов из ИИ: ChatGPT, Perplexity, Claude, Gemini, Copilot, по доменам в Referer и меткам utm_source.
- Оба справочника можно менять в интерфейсе без правки кода.

## Этап 3. Прием данных (только реально работающие способы)
- Функция приема событий: сайт отправляет пачку событий со своим ключом. Сервер проверяет ключ, домен и формат, сам определяет бота или источник и сохраняет событие с привязкой к сайту.
- Готовый PHP-сборщик для хостинга клиента: несколько строк в начале сайта. Он отправляет обращения ботов (URL, статус, User-Agent) и визиты с ИИ-Referer, не тормозит сайт и молча пропускает ошибки.
- Инструкция и скрипт для VPS: отправка access-логов nginx/apache (cron + скрипт). Работает только при наличии доступа к серверу клиента.
- Веб-аналитика (Метрика/GA): в этом этапе только карточка «Не подключен». Позже ее можно подключить через официальный API с токеном клиента. Имитации нет.

## Этап 4. Интерфейс
- Новый пункт меню в админке. Его видит только администратор, при открытии по ссылке без прав показывается ошибка 403.
- Фильтры: период (сегодня / 7 / 30 дней / свой диапазон), сайт, тип активности, бот или источник.
- Карточки: запросы ботов, уникальные URL, визиты из ИИ, число ИИ-источников, последнее обновление. Каждый показатель считается отдельно.
- Вкладка «ИИ-боты»: график по дням, топ страниц, журнал событий с пагинацией.
- Вкладка «Переходы из ИИ-чатов»: визиты по источникам, посадочные страницы, график, последний визит, способ определения перехода, пометка о неопределенных переходах.
- Вкладка «Сайты и подключения»: реестр, ключи, статусы, инструкции по подключению.
- Выгрузка в CSV из того же набора данных, по которому строятся график и таблицы.
- Корректный вид на мобильных.

## Этап 5. Проверка и отчет
- Проверка под обычным пользователем: пункта меню нет, страница закрыта, данные по запросу не отдаются.
- Тестовая отправка события с ключом. В отчете она помечена как проверка и сразу удаляется.
- Отчет: какие файлы и таблицы созданы, какие правила доступа действуют, что работает сразу, что требует доступа к хостингу или VPS клиента, пошаговое подключение первого сайта.

## Технические детали
- Таблицы: `monitor_sites`, `monitor_bot_signatures`, `monitor_ai_sources`, `monitor_events` (site_id, kind bot|referral, bot_id/source_id, url, status, ua, referrer, visitor_hash, occurred_at), `monitor_ingest_keys` (hash). Индексы по (site_id, occurred_at) и (site_id, kind).
- RLS: доступ только через `has_role(auth.uid(),'admin')`. Запись событий только через функцию с service role. Доступа для anon нет.
- Функции: `monitor-ingest` (ключ, zod-валидация, лимиты на размер пачки и частоту), `monitor-admin` (verifyAuth + requireAdmin: ключи, проверка подключения). Агрегаты считаются SQL-функциями с проверкой роли администратора.
- Посетители считаются по хешу IP+UA с суточной солью, сырой IP не хранится.
- Фронтенд: `src/features/ai-traffic-monitor/*`, маршрут под `ProtectedRoute requiredRole="admin"`, пункт в AppSidebar, переводы RU/EN.
